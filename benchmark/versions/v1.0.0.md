**Files**

- `benchmark/data/v1.0.0/examples.jsonl` — canonical records (one JSON object per line)
- `benchmark/data/v1.0.0/examples.csv` — flattened for spreadsheets
- `benchmark/data/v1.0.0/examples.parquet` — columnar copy
- `benchmark/data/v1.0.0/manifest.json` — counts, partitions, content hash, provenance

**Reproducing this release**

```bash
teb dataset build
teb dataset validate benchmark/data/v1.0.0/examples.jsonl
```

`teb dataset build` is deterministic: it reads the seed files in
`benchmark/seed/`, pins a fixed release timestamp, assigns partitions by
`sha256(example_id)`, and writes byte-identical files. The content hash covers
only substantive fields (ingestion metadata is excluded), so it is stable across
machines and rebuilds. `pytest tests/unit/test_reproducibility.py` asserts this.

**Provenance and licensing**

All records were authored for this benchmark. No copyrighted corpus was scraped
or redistributed. Idioms used are traditional/public-domain expressions. The
data is released under CC-BY-4.0; the code under MIT.

**How the hash changed from pre-release builds**

Early builds hashed the whole record including a per-build `created_at`
timestamp, so the hash changed on every rebuild and no two builds were
byte-identical. That defect is fixed; see `CHANGELOG.md`.

**Future versions**

New releases must increment the version directory (`benchmark/data/vX.Y.Z/`) and
record a new `benchmark/versions/<version>.md` note. Do not silently edit a
released version — evaluations reference the dataset by version and content hash.
